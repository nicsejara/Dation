# 5. STATE SEMANTICS

## LOCKED

Dependencia/upstream requerido no satisfecho.

Ejemplo:

D2 antes de tener D1 aprobado.

---

## DATA_REQUIRED

Dependencias satisfechas, pero faltan inputs requeridos.

Ejemplo:

D1 sin Demand o Resources publicados.

---

## READY

Todos los requisitos de negocio/datos/dependencias están satisfechos.

READY significa:

> el nodo está preparado para ser configurado/ejecutado.

NO significa automáticamente:

- que el usuario tenga permisos;
- que el runtime esté disponible;
- que ya exista una Run;
- que esté aprobado.

Esas dimensiones deben mantenerse separadas.

---

## IN_PROGRESS

Existe Run vigente:

```text
QUEUED / RUNNING
```

según lifecycle actual.

---

## COMPLETED

Existe resultado publicado de la Run vigente y pendiente de aprobación.

---

## APPROVED

Existe aprobación vigente del resultado actual y sus read sets/contexto permanecen frescos.

---

## COMING_SOON

Definition reconocida pero sin implementación ejecutable.

Nunca debe producir CTA de ejecución.

---

## NOT_APPLICABLE

El nodo no aplica al contexto/resultados.

Ejemplo futuro válido:

D2 si D1 aprobado tiene cero Trips y el contrato establece no aplicabilidad.

No fabricar una Run vacía.
